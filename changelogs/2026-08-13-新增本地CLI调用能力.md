# 新增本地 CLI 调用能力（youyi 命令行入口）

日期：2026-08-13
关联文档：设计方案 v0.7 §5.4、PRD 模块 I

## 背景与方案

产品定位不变（值守 + 中继），在现有基础上新增**第三个上行入口**：`youyi` 命令行工具，
让用户与本机其他程序能以纯命令行方式调用哨兵的既有操作（状态查询 / 透传 / 放行确认 / 全部停止）。

核心设计决策：

1. **CLI 不是新能力面**——文本消息进入与微信上行完全相同的消息路由器，
   高危拦截、远程放行开关、「全部停止」二次确认、审计日志全部照常生效；
2. **复用现有基础设施**——CLI 端点挂在 HookServer 上（仅回环绑定 + 路径 token 鉴权），
   客户端与桥接程序共用 `~/.youyi/bridge.json` 连接文件与同一套「零依赖脚本 +
   ELECTRON_RUN_AS_NODE 包装器」部署机制，用户机器不需要装 Node；
3. **回复就地返回**——路由器的回复出口参数化（`ReplyFn`），微信上行的回复发回渠道，
   CLI 上行的回复作为 HTTP 响应同步返回；Agent 的异步回复仍走通知渠道；
4. **与桥接的失败语义相反**——桥接 fail-open（不能阻断 Agent），CLI 明确报错退出
   （调用者需要知道失败）。

## 影响评估

- **安全面**：未新增任何绕过护栏的路径。CLI 端点与钩子端点同源（仅 127.0.0.1 +
  token 鉴权，token 存于 0600 的 `~/.youyi/server.json`），能拿到 token 的前提是
  已经能读取用户主目录；鉴权失败一律 403 且不泄露状态；
- **兼容性**：`HookServer` 第三个构造参数可选，既有调用方（含测试台）不受影响；
  `handleInbound` 的 options 为可选参数，微信链路行为不变；
  审计日志 channel 字段此前恒为 `wechat`，现在如实记录来源（微信链路仍为 `wechat`，无破坏）；
- **测试**：新增 `packages/app/test/cli-endpoint.test.ts`（鉴权 / 快照 / 同语义消息 /
  审计标注 / 非法 agentId），全量 107 个用例通过；
- **遗留说明**：CLI 的 `send` 会同步等待路由器整条流程（透传队列默认 90 秒超时 +
  无头拉起兜底），客户端默认 120 秒超时，超时只是不再等待、指令不丢；
  Agent 的最终回复仍回传通知渠道，CLI 侧暂不做长轮询（如有需要后续再评估）。
