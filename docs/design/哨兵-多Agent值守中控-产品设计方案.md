# 「哨兵」多 Agent 值守中控 — 产品设计方案 v0.7

> 一句话定位：**一个常驻个人电脑的"值守+遥控"中控。自动发现并接入你电脑上的多个 AI 应用，通过 Hook 机制实时感知任务状态；微信一个渠道搞定一切——收通知、发指令、和 Agent 对话，全部原样透传。**

> v0.7 变更说明（本地 CLI 调用）：
> 1. 新增**本地 CLI 入口**：`youyi` 命令行工具，让用户与本机其他程序能以纯命令行方式调用哨兵的既有操作（状态查询 / 透传 / 放行确认 / 全部停止）；
> 2. CLI 是**第三个上行入口**（与微信上行、桌面 UI 并列），复用同一个消息路由器，不新增任何绕过安全护栏的路径；产品定位不变，哨兵仍只做路由 + 透传 + 回传。

> v0.6 变更说明（渠道统一）：
> 1. **微信 JS-SDK 为唯一主渠道（双向）**：不仅能发通知，还能像 chatbot 一样收发对话；消息形态为**文本/图片/语音**（无卡片按钮）；
> 2. 飞书 / 钉钉降为**可选增强渠道**（其卡片按钮交互作为增强体验，非必需）；
> 3. 新增**回复回传**：Agent 对用户消息的回复原样回传微信，形成"用户 ↔ Agent"直接对话（哨兵只做中继）；
> 4. 语音指令（微信语音 → 转文字 → 透传）列为 Next 增强；
> 5. 产品边界不变：哨兵无 AI 对话能力，只做路由 + 透传 + 回传。

---

## 1. 产品概述

### 1.1 问题

普通用户电脑上装了多个 AI 应用（Claude Code、ChatGPT、AI IDE、各类 Agent 助手）。派了长任务后只能守在电脑前：等结束、等确认（执行代码、访问文件、继续下一步）。错过确认 → 任务卡死；不知道进度 → 反复刷屏。

### 1.2 核心价值主张

> **一次安装，自动值守；微信一条龙——收通知、发指令、和 AI 对话。**
> 让 AI 干着活，你去忙你的——需要你的时候，微信上回一句。

### 1.3 产品边界（重要）

**哨兵不是聊天机器人**：
- 无 AI 对话能力，不做语义理解、不做消息加工；
- 对话发生在"**用户 ↔ Agent**"之间：用户消息原样透传给 Agent，Agent 的回复原样回传微信；
- 哨兵只做中继：① 路由（消息发给哪个 Agent）；② 透传（上行）；③ 回传（下行）；④ 状态自答（本职数据）。

## 3. 微信对话透传闭环（v0.6 核心）

```
① 用户在微信发消息/语音
      ↓
② 哨兵路由（默认最近活跃 / 显式指定）→ 原样透传
      ↓
③ Agent 自己理解语义并执行（新任务/继续/停止/重试…）
      ↓
④ 事件通知 + Agent 回复 → 原样回传微信
```

### 3.1 路由规则（哨兵唯一要做的判断）

| 消息 | 处理 | 谁处理 |
|------|------|--------|
| "继续" / "停止" / "新任务：xxx" 等 | 透传给目标 Agent | Agent 自己理解执行 |
| "跑得怎么样了" / "都有什么任务" | 哨兵自答状态卡片（文本） | 哨兵（本职） |
| "全部停止" | 广播给所有 Agent（强确认） | 哨兵转发 |
| "交给 Claude Code：xxx" / "@X xxx" | 显式指定路由 | 透传指定 Agent |

- **默认目标**：最近活跃的 Agent（最近有任务事件的）；
- **无法确定目标**：反问"发给哪个？Claude Code / ChatGPT / ..."；
- **对话回传**：Agent 的回复（如 Claude Code 会话输出）原样转发回微信，形成连续对话。

### 3.2 微信消息形态与交互

- 微信只能发**文本 / 图片 / 语音**，无卡片按钮；
- 通知消息 = 结构化文本 + **引导语**："Claude Code 有个任务完成了。回复：继续 / 停止 / 状态 / 新任务：xxx"；
- 用户回复 = 打字或语音 → 透传（**语音转文字列为 Next**，依赖 SDK/本地 ASR）；
- 图片透传（用户给 Agent 发截图等）按 SDK 能力支持。

### 3.3 透传安全

- 用户主动发的消息不拦阻、不修改；
- 保留安全点：① "全部停止"强确认；② 路由到非默认目标提示一次；③ 审计日志（本地）。

## 4. 渠道（v0.6：微信唯一主渠道）

| 渠道 | 通知（下行） | 透传对话（上行） | 消息形态 | 角色 |
|------|:---:|:---:|---------|------|
| **微信（JS-SDK）** | 支持 | **支持** | 文本 / 图片 / 语音 | **唯一主渠道（双向）** |
| 飞书 | 支持 | 支持 | 卡片（**带按钮**） | 可选增强（按钮交互） |
| 钉钉 | 支持 | 支持 | 卡片（**带按钮**） | 可选增强（按钮交互） |
| 企业微信 | 支持 | 受限（需企业主体） | 文本 | 可选（仅通知） |
| 邮件 | 支持 | 不支持 | 文本 | 兜底 |

- **主备降级**：通知默认微信，连续 2 次失败切备选（飞书/钉钉/邮件）；
- **按钮 vs 引导语**：飞书/钉钉卡片可点按钮（继续/停止/暂缓提醒）；微信以引导语文字承载同等能力。

## 5. 系统架构（Electron 落地）

```
Electron 应用
├── 主进程（Node.js，常驻后台）
│   ├── Hook 服务（本地接收端点 + 各 Agent Hook 注册管理）
│   ├── CLI 网关（本地命令行入口：状态查询 / 透传 / 放行，与微信共用消息路由器）
│   ├── 应用感知引擎（兜底：文件监控 chokidar + 进程存活检测）
│   ├── 事件引擎（统一事件模型 + 任务状态机 + 聚合去重）
│   ├── 消息路由器（路由 + 透传 + 回复回传；状态自答；全部停止广播）
│   ├── 通知管家（打扰档位 + 免打扰时段 + 主备降级）
│   ├── 渠道适配（微信 JS-SDK 双向 + 飞书/钉钉可选 + 企微/邮件）
│   └── 系统集成（托盘 / 开机自启 / 自动更新 / 崩溃自愈）
├── 渲染进程（Dashboard UI：任务卡片 / 首次引导 / 设置）
├── youyi CLI（零依赖命令行客户端，部署于 ~/.youyi/bin，经回环 HTTP 调用主进程）
└── 本地存储（SQLite · better-sqlite3 · 默认不上云）
```

**Electron 启动生命周期约束**：主进程注册的 `activate`、`second-instance` 等事件，在应用完成 `ready` 且业务初始化完成前不得创建 `BrowserWindow`；启动期间的打开请求应延迟到初始化完成后处理。所有窗口创建路径都必须服从这一约束，避免打包应用在启动竞态下崩溃。

### 5.1 接入：Hook 机制为主

| Agent | Hook 接入 | 透传/回传通道 | 备注 |
|-------|:---:|:---:|------|
| Claude Code | 官方 Hooks | CLI/会话 I/O | 旗舰示范 |
| ChatGPT | 事件回调（待实测） | 待实测 | 实现期对接 |
| Workbuddy | 事件回调（待实测） | 待实测 | 实现期对接 |
| Qoder Work | IDE 事件回调（待实测） | 待实测 | 实现期对接 |
| Trae Work | IDE 事件回调（待实测） | 待实测 | 实现期对接 |
| OpenClaw | 事件回调（待实测） | 待实测 | 实现期对接 |
| Hermes | 事件回调（待实测） | 待实测 | 实现期对接 |

**自动发现**：安装后扫描本机运行的 Agent + 注册 Hook，用户只做**勾选**；无 Hook 自动回退日志监控（L1）。

### 5.2 统一事件模型

```json
{
  "event_id": "evt_8f3a",
  "agent_id": "claude-code",
  "task_id": "task_9c2b",
  "type": "task_failed",
  "severity": "critical",
  "title": "数据清洗脚本执行失败",
  "detail": "第 3 步：读取 xlsx 报错",
  "status": "FAILED",
  "occurred_at": "2026-08-11T10:20:33+08:00",
  "task_meta": { "started_at": "...", "progress": 0.6 },
  "source": { "hook": "notification", "raw": "<原始事件>" }
}
```

6 种事件：`task_started / task_progress / task_completed / task_failed / auth_required / task_stalled`

### 5.3 任务状态机

`PENDING → RUNNING ⇄ NEEDS_AUTH → COMPLETED / FAILED / STALLED`

| 事件 | 通知行为（标准档） | 说明 |
|------|-------------------|------|
| task_started | 不通知 | 启动卡死计时 |
| task_progress | 不通知 | 只更新状态 |
| task_completed | 低优先级 | 免打扰时段内攒成早报 |
| task_failed | 高优先级即时 | 附人性化原因 |
| auth_required | 最高优先级即时 | "Claude Code 需要你确认一下" |
| task_stalled | 高优先级即时 | 超过预期时长无进度 → 自动标记 |

### 5.4 本地 CLI 调用（v0.7）

> 定位：给本机用户与本机其他程序一个**纯命令行的调用入口**，能力集合与微信上行完全一致，不多不少。

```
youyi CLI（~/.youyi/bin/youyi）
  ↓ 读 ~/.youyi/bridge.json（端口 + token + 存活 PID）
  ↓ 回环 HTTP（127.0.0.1，路径 token 鉴权，与 Hook 端点同一服务）
主进程 CLI 网关
  ├── GET  /cli/:token/state    → 结构化状态快照（任务 / 待确认 / Agent，供 --json 脚本消费）
  └── POST /cli/:token/message  → 文本进消息路由器（与微信上行同一条路径），回复同步返回给调用方
```

- **同一路由器、同一护栏**：高危拦截、远程放行开关、「全部停止」二次确认、审计日志对 CLI 全部生效；审计记录的渠道标注为 `cli`；
- **回复就地返回**：微信上行的回复发回微信；CLI 上行的回复作为 HTTP 响应返回给命令行（Agent 的异步回复仍走通知渠道）；
- **命令集**：`status`（状态自答）/ `send [--agent id] <text>`（透传）/ `approve` `deny`（放行/拒绝）/ `stop-all [--confirm]`（强确认保留两步）/ `agents`；`--json` 输出供脚本与其他程序调用；
- **零依赖部署**：CLI 与桥接程序同机制——零依赖脚本 + 包装器复用哨兵自带 Electron 作为 Node 运行时，随主进程启动部署到 `~/.youyi/bin`，用户机器不需要装 Node；
- **哨兵未运行时**：CLI 明确报错退出（不同于钩子桥接的 fail-open——桥接不能阻断 Agent，而 CLI 调用者需要知道失败）。

## 6. 用户交互（微信里的体验）

### 6.1 通知（微信，文本+引导语）

```
[Claude Code] 数据清洗任务需要你确认
"是否允许访问 /Users/aliciawu/Documents/销售数据.xlsx？"
回复：继续 / 停止 / 状态 / 交给 ChatGPT：xxx
```

### 6.2 发指令（打字或语音）

- "别跑了" → 透传最近活跃 Agent → Agent 停止 → 回传结果；
- "新任务：整理 5 月销售数据" → 透传 → Agent 开始执行 → Hook 上报 → 通知；
- "跑得怎么样了" → 哨兵自答状态文本。

### 6.3 首次引导（5 步，约 5 分钟）

`安装启动 → 自动发现并勾选 Agent → 扫码绑定微信 → 选择打扰档 → 开始值守`

（飞书/钉钉为可选增强，绑定与否不影响核心体验）

**打扰档位**：安静（仅失败/需确认/卡住）/ 标准（默认，+完成）/ 全量（+关键进度）；免打扰时段默认 22:00-08:00。

## 8. 技术挑战与对策

| 挑战 | 等级 | 对策 |
|------|------|------|
| 各 Agent Hook / 透传回传通道异构 | 高 | 统一 Hook 适配层；Claude Code 先行验证，其余实现期逐个对接；日志兜底 |
| 微信无卡片，交互靠文本引导语 | 中 | 通知模板内置引导语；语音指令补位（Next） |
| 语音转文字依赖 | 中 | 优先用 SDK 自带能力；本地 ASR 兜底 |
| 路由准确性（防发错 Agent） | 中 | 默认最近活跃 + 非默认目标提示一次 |
| "全部停止"等广播操作安全 | 高 | 强确认 + 审计日志 |
| 普通用户无配置能力 | 高 | 自动发现 + 勾选式接入；高级配置折叠 |
| 厂商升级导致 Hook 失效 | 中 | Hook 适配层热更新；日志兜底 |
| 隐私信任（监控 + 透传） | 高 | 本地优先、不上云、只收必要事件、一键清除 |

## 9. 指标体系（免费产品）

### 北极星指标
**周活跃监控任务数**——每周被哨兵成功感知并管理的 Agent 任务数。

### 驱动指标
| 指标 | 目标（示例） |
|------|-------------|
| 首次引导完成率（激活率） | >60% |
| 人均监控 Agent 数 | ≥2 |
| 事件捕获率（Hook 事件 / 实际任务抽样） | >95% |
| 通知送达率 | >99% |
| 透传/回传成功率（消息 → Agent → 微信） | >95% |
| 确认/授权请求响应时长 | 中位数 <10min |

### 健康指标
| 指标 | 说明 |
|------|------|
| 误报率（STALLED 误报） | <5% |
| 用户降噪行为比例 | 反映打扰程度 |
| 周留存 | 免费工具看"下周长" |

## 10. 非目标（Non-goals）

- **不做 Agent 本体**：不生成内容、不代替 AI 干活；
- **不做 AI 对话/语义理解**：消息原样透传，哨兵只做中继；
- **不做任务编排/调度**：不是自动化工作流工具；
- **不做远程执行授权**（安全红线，Later 谨慎评估）；
- **不做开发者 SDK / 规则编辑器**（用户是普通用户）；
- **不做团队/多用户版**；
- **事件数据默认不上云**。
