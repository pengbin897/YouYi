# 「哨兵」多 Agent 值守中控 — MVP PRD

> 版本：v1.0（基线）｜ 基于产品设计 v0.6 + 交互原型 v0.7 确认
> 文档状态：待评审｜ 目标读者：工程、设计、测试

---

## 1. Problem Statement

普通用户电脑上同时安装多个 AI 应用（Claude Code、ChatGPT、AI IDE 等）。给它们派发长任务后，用户必须**值守在电脑前**：等待任务结束、等待 Agent 请求确认（执行代码、访问文件、继续下一步）。错过确认会导致任务**静默卡死数小时**；不知道进度导致**反复刷屏**；多个 Agent 并行时**没有全局视图**，状态混乱。

现有方案均不满足：各厂商移动端只覆盖自家单 Agent；Zapier 等自动化平台做工作流编排、不感知 Agent 任务事件；Bark/Server酱 等只解决"通知怎么发出去"、不解决"事件从哪感知"。**跨 Agent 任务感知 × 微信双向通道 × 零配置门槛**是明确的空白带。

不解决的代价：用户时间与算力浪费、任务因错过授权而失败、多 Agent 工作流难以管理；产品侧失去抢占"Agent 生态基础设施"窗口的机会。

## 3. Non-Goals（v1 明确不做）

| 不做 | 原因 |
|------|------|
| 不做 Agent 本体（不生成内容、不代跑任务） | 产品定位为值守/中继，非 AI 执行者 |
| 不做 AI 对话/语义理解（消息**原样透传**） | 哨兵无 AI 能力，语义由 Agent 自己理解（产品哲学） |
| 不做任务编排/调度（非 Zapier 类） | 定位差异，避免范围蔓延 |
| 不做远程执行授权 | 安全红线；仅"通知 + 回电脑处理"，远程确认留 Later 谨慎评估 |
| 不做规则编辑器 / 开发者 SDK | 目标用户是普通用户 |
| 不做团队/多用户版 | 个人工具定位 |
| 事件数据不上云 | 本地 SQLite 存储，隐私底线 |
| 微信语音指令转文字 | P1（依赖 SDK/ASR），不进 MVP |
| 浏览器扩展 / 远程状态页 / Linux 版 / 社区 Profile 共建 | P2，路线图 Later |

## 4. User Stories（按优先级）

1. **作为普通用户**，我希望安装后哨兵自动发现我电脑上的 AI 应用、我只勾选即可，以便**不需要配置任何路径或技术概念**。
2. **作为正在开会的用户**，我希望 Agent 需要确认时微信立刻收到通知，回一句"继续"即可放行，以便**不因错过授权导致任务卡死**。
3. **作为晚间派任务的用户**，我希望任务完成/失败时收到微信通知、免打扰期间的任务早上汇总，以便**睡前批量派活、早上统一看结果**。
4. **作为并行跑多任务的用户**，我希望任务卡住时自动收到提醒，以便**避免数小时无声等待**。
5. **作为在外的用户**，我希望在微信里发"新任务：xxx"就能给最近活跃的 Agent 派活，以便**不在电脑前也能继续推进工作**。
6. **作为怕打扰的用户**，我希望选择"安静档"+免打扰时段，以便**只在失败/需确认/卡住时被打扰**。
7. **作为关心安全的用户**，我希望所有透传与操作有审计日志、误发时可"全部停止"并强确认，以便**放心远程控制**。
8. **边界场景**：Agent 未运行/未被发现时给出可操作提示；渠道绑定失败、发送失败时明确告知并自动降级；微信不可用时切备选渠道。

## 5. Requirements

> P0=MVP 必须｜P1=上线后快速跟进｜P2=架构预留

### 模块 A：Electron 应用骨架

**A1 Electron 跨平台应用（P0）**
- macOS 12+ / Windows 10+，统一代码库；托盘常驻。
- 验收：
  - [ ] 双端安装包可安装、启动，托盘图标常驻
  - [ ] 关闭主窗口进程不退出（close-to-tray），托盘可恢复窗口
  - [ ] 开机自启可开关（默认关，引导时提示开启）

**A2 稳定性基线（P0）**
- 崩溃自愈（watchdog 重启）+ 自动更新（electron-updater）。
- 验收：
  - [ ] 主进程异常退出后 10s 内自动重启，任务状态不丢失
  - [ ] 新版本发布后自动下载并提示重启安装

### 模块 B：Hook 接入与自动发现

**B1 本地 Hook 接收端点（P0）**
- 哨兵启动本地 HTTP 服务（仅绑定 `127.0.0.1`），接收各 Agent Hook 推送的事件。
- 验收：
  - [ ] 端点仅监听 localhost，外部不可达
  - [ ] 收到事件后校验来源（预注册 Agent ID），未知来源拒绝并记日志

**B2 自动发现（P0）**
- 扫描本机运行进程与常见安装路径，识别 7 个目标 Agent，生成候选清单。
- 验收：
  - [ ] 7 个 Agent（Claude Code / ChatGPT / Workbuddy / Qoder Work / Trae Work / OpenClaw / Hermes）有对应识别规则
  - [ ] 运行中的 Agent 标记"运行中"，并默认勾选
  - [ ] 已安装但未运行的 Agent 可勾选，运行时自动补连
  - [ ] 未识别的应用不出现；提供"手动添加"入口（折叠于高级设置）

**B3 Agent 适配与能力分级（P0）**
- 首发完整接入：Claude Code（L3 授权感知 + 双向透传）；ChatGPT（L2 + 透传）。其余 5 个走通用 Hook/日志规则（L1）。
- 验收：
  - [ ] Claude Code 事件完整映射 6 种统一事件，含"需要确认"识别
  - [ ] ChatGPT 可识别任务开始/完成/失败
  - [ ] 其余 Agent 至少可识别开始/完成/失败（L1）
  - [ ] 无 Hook 的 Agent 自动回退日志监控，能力降级但在 UI 如实标注

**B4 适配器热更新（P1）**
- 解析规则可静默下发更新，Agent 升级导致失效时自动回退日志兜底。

### 模块 C：事件引擎

**C1 统一事件模型（P0）**
- 6 种事件：`task_started / task_progress / task_completed / task_failed / auth_required / task_stalled`；统一 Schema（event_id、agent_id、task_id、type、severity、title、detail、status、occurred_at、task_meta、source）。
- 验收：
  - [ ] 所有 Agent 的事件归一化为统一模型，UI 与通知只依赖统一模型
  - [ ] 事件含 task_id 关联，同一任务的事件可聚合

**C2 任务状态机（P0）**
- `PENDING → RUNNING ⇄ NEEDS_AUTH → COMPLETED / FAILED / STALLED`。
- 验收：
  - [ ] 非法状态迁移被拒绝并告警（如 COMPLETED 后再次 RUNNING）
  - [ ] NEEDS_AUTH 等待期间重复确认事件不重复通知

**C3 聚合去重（P0）**
- 连续进度事件只更新状态不通知；10 分钟内同 Agent 多个完成事件合并汇总。
- 验收：
  - [ ] 同一任务连续 10 条 progress 仅产生 1 次状态更新、0 次通知
  - [ ] 10 分钟内同 Agent ≥2 个 completed 合并为 1 条汇总通知

**C4 卡死检测（P0）**
- 任务进入 RUNNING 后超过预期时长（按 Agent 预设、可调，默认 30min）无进度 → 标记 STALLED 并推送。
- 验收：
  - [ ] 超时无进度自动标记 STALLED 并触发高优先级通知
  - [ ] 中途有进度事件则重置计时，不误报
  - [ ] 误报率（人工抽样）<5%

**C5 事件持久化（P0）**
- 本地 SQLite 存储事件与任务记录，默认不上云。
- 验收：
  - [ ] 重启后任务状态与历史完整恢复
  - [ ] 提供"一键清除全部数据"

### 模块 D：消息路由器（核心差异化）

**D1 消息路由（P0）**
- 上行消息（微信/钉钉/飞书）→ 目标 Agent 判定：默认最近活跃 Agent；支持显式指定（"交给 Claude Code：xxx" / "@X xxx"）；无法判定时反问候选。
- 验收：
  - [ ] 无指定时透传给最近有任务事件的 Agent
  - [ ] "交给 X：内容" / "@X 内容" 精确路由到 X
  - [ ] 无最近活跃且未指定时，返回"发给哪个？"候选选择
  - [ ] 路由到非默认目标时提示一次"将发给 X，确认？"（防发错）

**D2 原样透传 + 回复回传（P0）**
- 用户消息原样透传给 Agent（不做语义加工）；Agent 回复原样回传渠道，形成对话。
- 验收：
  - [ ] 用户文本消息 100% 原样透传（无改写/无前缀注入）
  - [ ] Agent 回复在可配置时限内回传（透传/回传成功率 >95%）
  - [ ] 透传失败时返回明确错误并提示重试

**D3 状态自答（P0）**
- "状态" / "都有什么任务" 等由哨兵自身返回（不打扰 Agent）。
- 验收：
  - [ ] 触发状态类消息时返回运行中任务列表（Agent、任务名、进度、耗时）
  - [ ] 无任务时返回空态友好文案

**D4 全部停止广播（P0）**
- 触发"全部停止"时向所有已接入 Agent 广播停止指令；需强确认（二次确认 + 明确后果提示）。
- 验收：
  - [ ] 首次输入"全部停止"仅回显确认，不直接执行
  - [ ] 确认后向所有 Agent 下发，并返回各 Agent 执行回执
  - [ ] 操作记录审计日志

**D5 审计日志（P0）**
- 记录：透传内容摘要、目标、时间、渠道、结果；本地存储可导出。
- 验收：
  - [ ] 每条透传/广播/确认操作均有审计记录
  - [ ] 审计日志可在面板查看、一键导出

### 模块 E：渠道层

**E1 微信 JS-SDK 双向主渠道（P0）**
- 通知（下行）+ 消息收发（上行，chatbot 式）+ 回复回传；消息形态文本/图片/语音，无卡片按钮。
- 验收：
  - [ ] 任务事件通知以文本+引导语推送："回复：继续 / 停止 / 状态 / 新任务：xxx"
  - [ ] 用户文本消息可上行并透传；Agent 回复回传微信
  - [ ] 通知与 Agent 回传消息在样式/前缀上可区分（避免混淆）
  - [ ] 发送失败自动重试，重试 2 次失败转降级（见 E6）

**E2 钉钉 / 飞书渠道（P1，可选增强）**
- 群机器人 webhook 接入（用户粘贴链接）；支持消息上行透传；后续支持卡片按钮。
- 验收：
  - [ ] webhook 校验、测试发送、绑定成功提示
  - [ ] 群内消息可上行并透传

**E3 企业微信（P1）**
- 群机器人 webhook，仅通知下行；标注"需企业主体"的能力限制。

**E4 邮件兜底（P0）**
- 主渠道不可用时降级发送；无上行能力。
- 验收：
  - [ ] 降级触发时发送邮件并提示"微信不可用，已邮件通知"

**E5 主备降级（P0）**
- 默认主=微信，备=钉钉/飞书/邮件；主渠道连续 2 次发送失败自动切换，面板提示。
- 验收：
  - [ ] 主渠道连续 2 次失败后自动切备选并提示用户
  - [ ] 恢复后自动切回主渠道（或提示手动切回）

**E6 送达回执（P1）**：通知发送结果（送达/失败）回写面板通知中心。

### 模块 F：通知管家

**F1 三档打扰（P0）**
- 安静：仅 failed / auth_required / stalled；标准：+completed；全量：+关键进度。
- 验收：
  - [ ] 三档切换即时生效，历史配置保留
  - [ ] 各档位下通知集合与定义严格一致

**F2 免打扰时段（P0）**
- 默认 22:00-08:00，期间仅推 auth_required（最高优先级），其余入早报。
- 验收：
  - [ ] 时段内 completed 不即时推送，进入早报
  - [ ] 时段内 auth_required 仍即时推送
  - [ ] 时段可自定义

**F3 早报汇总（P0）**
- 免打扰期间完成/失败任务早上 8 点汇总推送。
- 验收：
  - [ ] 早报按 Agent 分组列出完成/失败任务与结果摘要
  - [ ] 无任务时不发空早报

**F4 单任务静音（P1）**：对单个任务取消后续通知，可恢复。

### 模块 G：首次引导与 UI

**G1 首次引导 5 步（P0）**
- 欢迎 → 自动发现勾选 → 绑定渠道（三选一：微信/钉钉/飞书，一次一个）→ 打扰档位 → 开始值守。
- 验收（对应交互原型）：
  - [ ] 5 步流程可完成、可回退，进度指示正确
  - [ ] 渠道三选一单选切换，绑定面板随渠道变化（微信=扫码 / 钉钉、飞书=webhook 输入）
  - [ ] 绑定成功后 Step5 汇总动态显示所选渠道与状态
  - [ ] 中断引导后再次打开可续接（localStorage）

**G2 卡片式任务面板（P0）**
- 任务卡片：Agent 标识 + 任务名 + 状态色（进行中=蓝/完成=绿/失败=红/待确认=橙/卡住=红）。
- 验收：
  - [ ] 状态色与事件类型映射一致
  - [ ] 卡片可点击查看详情（进度、耗时、结果摘要、原始事件）
  - [ ] 空态（无任务）有友好引导

**G3 托盘菜单（P0）**
- 快速查看运行中任务数、最近事件、一键打开面板。
- 验收：
  - [ ] 托盘菜单实时显示运行中任务数与最近事件
  - [ ] 点击托盘可恢复主窗口

**G4 设置页（P0）**
- 渠道管理、打扰档位、免打扰时段、开机自启、手动添加 Agent、一键清除数据；高级项折叠。
- 验收：
  - [ ] 所有引导中的配置可在设置页修改并即时生效
  - [ ] "一键清除数据"二次确认后执行

**G5 通知中心 / 统计（P1）**：历史通知列表；"本月 AI 帮你干了多少活"统计。

### 模块 H：安全与隐私（P0）

- 验收：
  - [ ] 事件与审计数据仅存本地 SQLite，无云上传代码路径
  - [ ] Hook 端点仅绑定 127.0.0.1，请求来源校验
  - [ ] 卸载/清除时删除全部本地数据
  - [ ] 隐私说明页明示："我们看不到你的任务内容"

### 模块 I：本地 CLI 调用（v0.7 追加）

**I1 CLI 网关（主进程）**
- HookServer 上新增两个仅回环可达的端点，沿用现有路径 token 鉴权：
  - `GET /cli/:token/state`：结构化状态快照（活跃任务、待确认请求、Agent 状态、最近事件）；
  - `POST /cli/:token/message`：文本消息进入与微信上行**同一个消息路由器**，产生的回复同步返回给调用方。
- 验收：
  - [ ] token 错误返回 403，不泄露任何状态信息
  - [ ] 「状态」「继续」「停止」「全部停止」「交给 X：…」在 CLI 通道下与微信语义一致
  - [ ] 高危拦截、远程放行开关、「全部停止」二次确认对 CLI 全部生效
  - [ ] CLI 通道的透传/放行/广播操作写入审计日志，渠道标注为 `cli`

**I2 youyi 命令行客户端**
- 零依赖脚本（与桥接程序同铁律），读 `~/.youyi/bridge.json` 定位主进程；随主进程启动部署到 `~/.youyi/bin/youyi`（复用哨兵自带 Electron 作为运行时，无需用户安装 Node）。
- 命令集：`status` / `send [--agent id] <text>` / `approve` / `deny` / `stop-all [--confirm]` / `agents`；`status`、`agents` 支持 `--json`。
- 验收：
  - [ ] 哨兵未运行（连接文件缺失或 PID 不存活）时明确报错并以非 0 退出码结束
  - [ ] `youyi status --json` 输出机器可读 JSON，供脚本与其他程序消费
  - [ ] `youyi send` 能透传到目标 Agent 并把哨兵的确认回执打印到 stdout
  - [ ] `youyi stop-all` 保留两步强确认（`--confirm` 才执行）

## 6. Success Metrics

### 北极星
**周活跃监控任务数**：每周被哨兵成功感知并管理的 Agent 任务数。

### Leading Indicators（上线后逐周观测）
| 指标 | 定义 | 阈值 / 冲刺 |
|------|------|------------|
| 首次引导完成率 | 安装→完成 5 步引导 | >60% / 75% |
| 人均监控 Agent 数 | 活跃用户平均勾选数 | ≥2 |
| 事件捕获率 | 哨兵识别事件 / 抽样实际任务（人工核对） | >95% |
| 通知送达率 | 成功送达 / 应发 | >99% |
| 透传/回传成功率 | 用户消息→Agent→回传闭环成功 | >95% |
| 授权响应时长 | auth_required 到用户首个动作 | 中位数 <10min |

### Lagging Indicators（月度）
| 指标 | 目标 |
|------|------|
| 周留存（下周长） | ≥40% |
| 误报率（STALLED 抽样） | <5% |
| 降噪行为比例（关通知/切安静档） | <15%（超出说明打扰过度） |
| NPS（内测） | ≥40 |
